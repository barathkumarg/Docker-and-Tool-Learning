# Docker Security Basics

## Overview
Container security focuses on reducing the attack surface and limiting privileges.

## Key Concepts

### Run as a non-root user
- Avoid running containers as root whenever possible.
- Create a dedicated user in the image and use `USER` in the Dockerfile.

```dockerfile
FROM python:3.11-slim
RUN useradd -m appuser
USER appuser
```

### Read-only filesystem
- Use a read-only root filesystem when the app does not need to write to disk.
- This reduces the chance of tampering or accidental changes.

```bash
docker run --read-only alpine:latest sh
```

### Minimal images
- Use smaller base images such as `alpine` or `distroless`.
- Remove unnecessary packages and build artifacts.

## Useful Commands

```bash
docker run --user 1000:1000 myimage
docker run --read-only myimage
docker inspect <container>
```

## Insights
- Security hardening should be done gradually.
- Not every container can be fully read-only, so evaluate app requirements first.
- Small, minimal images and least-privilege execution are best practices.
