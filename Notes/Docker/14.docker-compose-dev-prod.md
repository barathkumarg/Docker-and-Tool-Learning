# Docker Compose for Development and Production

## Overview
Docker Compose can be used in both development and production workflows. The main difference is usually the amount of convenience, debugging, and environment-specific configuration.

## Key Concepts

### Development Compose
- Use bind mounts for faster local development.
- Enable debug settings and hot reloading.
- Keep the setup simple and developer-friendly.

```yaml
services:
  web:
    build: .
    ports:
      - "5000:5000"
    volumes:
      - .:/app
    environment:
      FLASK_ENV: development
```

### Production Compose
- Prefer stable images and environment variables.
- Use production-ready settings and avoid development-only mounts.
- Keep secrets and sensitive configuration separate.

```yaml
services:
  web:
    image: myapp:latest
    environment:
      FLASK_ENV: production
```

### Override files
- Use `docker-compose.override.yml` for local-only changes.
- Keep the base Compose file generic.

## Useful Commands

```bash
docker compose up -d
docker compose -f docker-compose.yml -f docker-compose.override.yml up -d
docker compose config
```

## Insights
- Development Compose focuses on convenience and iteration.
- Production Compose focuses on stability, security, and predictability.
- Override files are a clean way to separate local and production concerns.
