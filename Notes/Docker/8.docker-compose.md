# Docker Compose

## Overview
Docker Compose is a tool for defining and running multi-container Docker applications using a YAML file (`docker-compose.yml`).

## Basic Example

```yaml
version: '3'
services:
  web:
    build: .
    ports:
      - "5000:5000"
  redis:
    image: redis:alpine
```



Simple example:

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY app.py /app/app.py
EXPOSE 5000
LABEL maintainer="dev@example.com"
CMD ["python", "app.py"]
```

## Advanced Example with Networks, Volumes, Entrypoint & CMD

```yaml
version: '3.8'

services:
  web:
    build: .
    container_name: web_app
    ports:
      - "5000:5000"
    volumes:
      - ./app:/app
      - /app/node_modules
    environment:
      - FLASK_ENV=development
      - REDIS_HOST=redis
    entrypoint: ["python", "app.py"]
    command: ["--host", "0.0.0.0", "--port", "5000"]
    networks:
      - app-network
    depends_on:
      - redis
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    container_name: redis_cache
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    networks:
      - app-network
    command: redis-server --appendonly yes
    restart: unless-stopped

  db:
    image: postgres:15
    container_name: postgres_db
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: appdb
    volumes:
      - postgres-data:/var/lib/postgresql/data
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql
    networks:
      - app-network
    ports:
      - "5432:5432"
    restart: unless-stopped

networks:
  app-network:
    driver: bridge
    driver_opts:
      com.docker.network.bridge.name: br-app

volumes:
  redis-data:
    driver: local
  postgres-data:
    driver: local
```

## Commands

### Basic commands
- `docker compose up -d` — Start services in detached mode.
- `docker compose up -d --build` — Rebuild images and start services.
- `docker compose build` — Build or rebuild services without starting them.
- `docker compose ps` — List running services and containers.
- `docker compose logs -f` — Follow logs for all services.
- `docker compose logs -f <service>` — Follow logs for a specific service.
- `docker compose stop` — Stop running services.
- `docker compose start` — Start stopped services.
- `docker compose restart` — Restart services.
- `docker compose down` — Stop and remove containers, networks, and default volumes.
- `docker compose down --volumes --remove-orphans` — Remove containers, networks, volumes, and orphaned resources.

### Exec and run commands
- `docker compose exec <service> sh` — Open a shell inside a running container.
- `docker compose run --rm <service> <command>` — Run a one-off command inside a service container.
- `docker compose config` — Validate and view the final Compose configuration.
- `docker compose pull` — Pull the latest images for services.
- `docker compose scale <service>=<number>` — Scale a service to multiple replicas.
- `docker compose rm -f` — Remove stopped containers.

### Example usage
```bash
docker compose up -d --build
docker compose ps
docker compose logs -f web
docker compose exec web sh
docker compose run --rm web python app.py
docker compose down --volumes
```

## Key Features Explained

### Networks (Network Bridge)
- `networks`: Defines custom networks for service communication.
- `driver: bridge`: Creates a bridge network (default for Compose).
- Services on the same network can communicate using service names as hostnames.
- Example: web service can reach redis using hostname `redis`.

### Volumes
- **Named volumes**: `redis-data:/data` — Persist data outside containers.
- **Bind mounts**: `./app:/app` — Mount local directory into container.
- **Anonymous volumes**: `/app/node_modules` — Exclude directories from sharing.
- `volumes` section: Defines named volumes used by services.
- Useful for database persistence, development code sharing, and data preservation.

### Entrypoint
- `entrypoint`: Specifies the command that runs when container starts.
- Example: `["python", "app.py"]` — Always runs Python with app.py.
- Overrides the `ENTRYPOINT` instruction in Dockerfile.
- Cannot be overridden by `docker-compose run` without `--entrypoint`.

### Command (CMD)
- `command`: Provides default arguments to the entrypoint.
- Example: `["--host", "0.0.0.0", "--port", "5000"]` — Passes arguments to Python app.
- Can be overridden with `docker-compose run <service> <new-command>`.
- If no entrypoint is specified, acts as the main executable.

## Use Cases

- Local development with multiple dependent services (databases, caches).
- Simplifies orchestration for small deployments or testing.
