# Docker Swarm, CI/CD, and Image Scanning

## Overview
Beyond single-host Docker usage, teams also use Docker Swarm, CI/CD pipelines, and image scanning to deploy and secure applications more reliably.

## Key Concepts

### Docker Swarm basics
- Docker Swarm is Docker's native orchestration tool.
- It manages a cluster of Docker nodes.
- Services can be deployed with `docker stack`.

```bash
docker swarm init
docker service create --name web nginx:alpine
docker stack deploy -c docker-compose.yml myapp
```

### Compose override files and production-ready patterns
- Use a base Compose file for common settings.
- Use `docker-compose.override.yml` for development-specific values.
- Keep production settings explicit and environment-driven.

```yaml
services:
  app:
    image: myapp:latest
    environment:
      NODE_ENV: production
```

### CI/CD with Docker images
- Build images in CI pipelines.
- Tag them with version numbers.
- Push them to a registry after tests pass.

```bash
docker build -t myapp:ci .
docker push myapp:ci
```

### Image scanning and vulnerability checks
- Scan images for known vulnerabilities.
- Use tools such as Docker Scout or external scanners.
- Review and fix issues before deployment.

```bash
docker scout cves myapp:latest
```

## Insights
- Swarm is useful for small production clusters and simple orchestration.
- Compose patterns become more powerful when development and production are separated clearly.
- CI/CD and scanning are essential for robust image delivery.
