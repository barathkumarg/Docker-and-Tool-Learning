

# Docker Images

## Overview

### What is a Docker Image?
Docker images are lightweight, standalone, and executable software packages that include everything needed to run an application: code, runtime, libraries, environment variables, and configuration files. They provide a consistent and reproducible environment for applications, making it easier to develop, test, and deploy across different platforms.

### Why Use Docker Images?
- Consistent environment across platforms
- Simplifies application deployment
- Isolates dependencies and configurations
- Enables easy versioning and rollback

## Creating a Docker Image

A Docker image is built from a file called a Dockerfile. This file contains instructions that tell Docker how to prepare the image step by step.

### Example Dockerfile
```dockerfile
FROM python:3.11-slim

LABEL maintainer="dev@example.com"
ARG APP_VERSION=1.0

RUN apt-get update && apt-get install -y curl

WORKDIR /app
COPY requirements.txt ./requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

COPY . /app

ENV PYTHONUNBUFFERED=1
ENV PORT=5000

EXPOSE 5000
VOLUME /app/data
USER appuser

ENTRYPOINT ["python", "app.py"]
CMD ["--host", "0.0.0.0", "--port", "5000"]
```

This is a complete example showing common Dockerfile instructions together.

### Build the Image
```sh
docker build -t myapp:latest .
```

- `-t` gives the image a name and tag.
- The `.` means Docker should look for the Dockerfile in the current folder.

## Common Dockerfile Instructions

These are the most important instructions used in a Dockerfile:

- `FROM` — Defines the base image to start from.
  - Example: `FROM ubuntu:22.04`

- `RUN` — Executes commands during image build.
  - Example: `RUN apt-get update`
  - Useful for installing packages and setting up the environment.

- `COPY` — Copies files from your computer into the image.
  - Example: `COPY . /app`

- `WORKDIR` — Sets the default folder inside the container.
  - Example: `WORKDIR /app`

- `ENV` — Sets environment variables inside the container.
  - Example: `ENV PORT=5000`

- `EXPOSE` — Declares the port the container will use.
  - Example: `EXPOSE 5000`
  - It does not open the port by itself.

- `ENTRYPOINT` — Defines the main command that always runs when the container starts.
  - Example: `ENTRYPOINT ["python", "app.py"]`

- `CMD` — Provides default arguments for the entrypoint or a default command.
  - Example: `CMD ["--host", "0.0.0.0"]`

- `LABEL` — Adds metadata to the image.
  - Example: `LABEL maintainer="dev@example.com"`

- `USER` — Sets the user that will run commands inside the container.
  - Example: `USER appuser`

- `VOLUME` — Creates a mount point for persistent data.
  - Example: `VOLUME /data`

- `ARG` — Defines build-time variables.
  - Example: `ARG APP_VERSION=1.0`

## Managing Docker Images

### List Images
```sh
docker images
```

### View Image History
```sh
docker history myapp:latest
```

This shows the layers and commands used to build the image.

### Remove an Image
```sh
docker rmi myapp:latest
```

### Pull an Image from Docker Hub
```sh
docker pull nginx:latest
```

### Push an Image to Docker Hub
```sh
docker tag myapp:latest yourname/myapp:latest
docker push yourname/myapp:latest
```

## Running a Container

After building an image, you can run it as a container:

```sh
docker run -d -p 5000:5000 --name myapp myapp:latest
```

- `-d` runs the container in the background.
- `-p` maps host port to container port.
- `--name` gives the container a name.

## Environment Variables

You can set environment variables in two common ways:

1. During container run:
```sh
docker run -e PORT=5000 myapp:latest
```

2. Inside the Dockerfile:
```dockerfile
ENV PORT=5000
```

To inspect environment variables in a running container:
```sh
docker inspect myapp
```

## Helpful Docker Commands

```sh
docker build --help
docker run --help
docker images --help
docker inspect --help
docker history --help
```

These help commands show the available options for each Docker command.
